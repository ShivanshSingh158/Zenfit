4. DETAILED LIFECYCLE & HYDRATION FLOW (BOOT TO RENDER)
================================================================================

```
[App Boot / Navigation to Plan Tab]
       │
       ▼
1. L1 Cache / AsyncStorage read:
   WellnessContext loads initialManifest?.userGymPlan (< 5ms).
       │
       ▼
2. Canonicalization Pass:
   canonicalizeUserGymPlan() sanitizes all customDays exercises, ensuring
   legacy names are mapped to 525 Hevy-standard canonical names.
       │
       ▼
3. Firestore onSnapshot Listener Subscribed:
   Listens to doc(db, 'user_gym_plans', uid).
   When server updates arrive, silently updates L1 cache, state, and disk cache.
       │
       ▼
4. GymSplitsScreen Mounts:
   Computes resolvedDays memo (1..7):
   For day 1..7:
     If userGymPlan?.customDays?.[i] exists -> Use customDay
     Else -> Default from basePlan (GYM_PLAN_PPL or GYM_PLAN_ARNOLD)
       │
       ▼
5. Active Day Resolved:
   selectedDayIndex defaults to current day of week (or Sunday=7).
   Renders active day's exercises, tier tags, and sets.
```

5. USER INTERACTION & MUTATION FLOWS
================================================================================

5.1 SWITCHING TEMPLATES (Arnold Split vs PPL)
--------------------------------------------------------------------------------
1. User taps "Templates" button on header -> Opens GymTemplateModal.
2. User selects "Arnold Split (Chest/Back, Shoulders/Arms, Legs)".
3. Calls applyMasterTemplate('arnold', schedulePattern) in WellnessContext.tsx.
4. Generates new customDays[1..7] mapping Arnold days according to schedulePattern.
5. Saves optimistically to L1 cache, disk cache, and fires setDoc to Firestore.
6. resolvedDays in GymSplitsScreen recalculates immediately.

5.2 SELECTING & VIEWING A DAY (Monday – Sunday)
--------------------------------------------------------------------------------
1. User taps day chip (e.g. "Wed" or "Sat") in horizontal selector.
2. Triggers setSelectedDayIndex(i) with haptic feedback.
3. activeDay updates to resolvedDays[i - 1].
4. Renders list of exercises for Wednesday with their target sets/reps/rest.

5.3 EDITING SETS & REPS FOR AN EXERCISE
--------------------------------------------------------------------------------
1. User taps on an exercise row's sets/reps badge -> Opens Edit Sets/Reps modal.
2. User chooses target sets (e.g. 4) and rep range (e.g. '6–8').
3. GymSplitsScreen copies current activeDay:
   const updatedExercises = [...activeDay.exercises];
   updatedExercises[exerciseIndex] = { ...exercise, targetSets, targetReps };
4. Calls updateMasterPlan(selectedDayIndex, { ...activeDay, exercises: updatedExercises }).
5. Updates userGymPlan.customDays in WellnessContext and writes to Firestore.

5.4 ADDING A NEW EXERCISE TO A DAY
--------------------------------------------------------------------------------
1. User scrolls to bottom of day's exercise list and taps "+ Add Exercise".
2. Opens AddExerciseModal with planDay={activeDay.planDay}.
3. User searches or picks an exercise from the 525 database.
4. If "Save permanently to routine" is checked:
   Appends new exercise to activeDay.exercises.
   Calls updateMasterPlan(dayIndex, updatedPlanDay).

5.5 SWAPPING AN EXERCISE WITH ALTERNATIVES
--------------------------------------------------------------------------------
1. User taps "•••" on exercise row -> Selects "Swap Exercise".
2. Navigates to ExerciseSwapScreen or opens ActiveSwapModal.
3. Queries EXERCISE_ALTERNATIVES[muscle] to show S-Tier and A+-Tier replacements.
4. User selects replacement exercise.
5. Updates exercise in activeDay and calls updateMasterPlan.

5.6 REORDERING EXERCISES IN A ROUTINE
--------------------------------------------------------------------------------
1. User taps "Move Up" or "Move Down" in exercise options sheet (or drag reorder).
2. Exercises array is re-indexed.
3. Calls updateMasterPlan(selectedDayIndex, { ...activeDay, exercises: reordered }).

5.7 RENAMING A ROUTINE DAY & FOCUS
--------------------------------------------------------------------------------
1. User taps edit pencil icon next to Day Title.
2. Opens RenameDayModal.
3. User enters new Routine Name (e.g. "Quad Destruction") and Focus string.
4. Calls updateMasterPlan(selectedDayIndex, { ...activeDay, name, focus }).

5.8 CHANGING SCHEDULE PATTERNS (e.g. Mon-Fri vs Mon-Sun)
--------------------------------------------------------------------------------
1. User taps settings gear icon -> Opens GymScheduleSettingsModal.
2. User switches pattern (e.g. 5-day Mon-Fri with Sat-Sun rest).
3. Re-maps workout days across customDays[1..7].
4. Calls updateFullMasterPlan(newCustomDays).

7. ARCHITECTURAL BOTTLENECK ANALYSIS OF CURRENT IMPLEMENTATION
================================================================================
Why the current Plan tab needs a Hevy-style rebuild:

1. Rigid Day-Index Locking:
   Currently, all routines MUST be tied to Day 1–7 (Monday through Sunday).
   Users cannot create a standalone routine (e.g. "Quick Arm Workout", "Hotel Bodyweight")
   without overwriting one of their 7 days of the week.

2. Monolithic Code Structure:
   src/screens/gym/GymSplitsScreen.tsx is 1,642 lines with 6 modal states embedded in
   the same component, causing frequent unnecessary re-renders.

3. Lack of "Start Routine" Direct Launch:
   In Hevy or Strong, users can tap "Start Routine" directly from the routines tab.
   In ZenFit currently, users must navigate to the Today tab, swap the routine onto
   today, and then start it.

4. Separation of Modular Routines vs Weekly Calendar:
   A modern architecture separates:
   - "Routines Library" (Collection of reusable modular workouts)
   - "Weekly Schedule" (Which routine is assigned to which day of the week)
   This allows unlimited routines while keeping the 7-day schedule clean and intuitive.
